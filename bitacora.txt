MINIRETO 2: La vitrina de Rueda Libre (página de inicio)
==================================================
Objetivo: estructurar el contenido de la página de inicio con encabezados, párrafos, listas, imágenes y enlaces.

1. Esquema de encabezados
- h1: Rueda Libre (único en toda la página, con el logo al lado).
- h2: ¿Quiénes somos?, Nuestros servicios, ¿Cómo alquilar?, Encuéntranos.
- h3 (dentro de "Nuestros servicios"): Alquiler de bicicletas, Recorridos guiados, Taller básico.
- Decisión: el número del encabezado indica la jerarquía (a qué sección pertenece), no el tamaño. Las secciones hermanas llevan el mismo nivel y no se saltan niveles.
- Error corregido: al principio puse los títulos en escalera (h2, h3, h4, h5). Lo corregí porque las cuatro secciones son del mismo nivel y los servicios van un nivel por debajo de "Nuestros servicios".

2. Contenido de los servicios
- Cada h3 tiene su párrafo debajo.
- strong (información clave): "incluye casco y candado" en el alquiler y "ajustes de frenos y cambios" en el taller.
- em (matiz): "pensadas para disfrutar sin afán" en los recorridos y "en el mismo día" en el taller.
- Decisión: strong marca importancia y em marca énfasis. No los uso para cambiar la apariencia, eso se hará con CSS.

3. Listas
- Lista numerada (ol): los 4 pasos para alquilar, porque el orden importa.
- Lista con viñetas (ul): los 3 beneficios del servicio, porque el orden no importa. Quedó dentro de "¿Quiénes somos?" con una frase que la presenta.
- Dentro de ol y ul solo van elementos li.

4. Imágenes
- Archivos en img/: portada.jpg, bicicleta.jpg, ruta.jpg (además de logo.jpg).
- Todas con ruta relativa (img/archivo.jpg), sin rutas del tipo C:\ o /home/.
- Todas con alt y con width definido (600 px la portada, 400 px las demás), sin height, para que no se deformen.
- Observación: cada foto pesa cerca de 1 MB y mide 1408 x 768 px. Funciona, pero conviene optimizarlas más adelante, porque se muestran a 600 y 400 px de ancho.
- Aprendizaje: el alt debe describir lo que realmente se ve en la foto, no una descripción de ejemplo.

5. Enlaces
- Externo (absoluto): búsqueda de Medellín en Google Maps. Lleva target="_blank" para abrir en otra pestaña y rel="noopener noreferrer" por seguridad.
- Correo: mailto:hola@ruedalibre.example (abre la aplicación de correo).
- Interno: desde el primer párrafo hacia #encuentranos. El h2 de "Encuéntranos" tiene id="encuentranos".
- Decisión: el id va en minúsculas y sin tilde, y debe coincidir exactamente con el href.

MINIRETO 3: Tarifas y rutas (tablas y enlaces entre carpetas)
==================================================

Objetivo: estructurar datos tabulares con tablas accesibles y conectar páginas ubicadas en carpetas distintas utilizando rutas relativas.

1. Creación de la página de tarifas (`paginas/tarifas.html`)

* Se creó el archivo `tarifas.html` dentro de la subcarpeta `paginas/`.
* Incluye la estructura base completa (DOCTYPE, `lang="es"`, codificación UTF-8, viewport y meta description propia).
* Título de la pestaña: `Rueda Libre | Tarifas y Recorridos`.

2. Tabla 1: Tarifas de alquiler de bicicletas

* Uso de etiquetas tabulares semánticas: `<table>`, `<caption>`, `<thead>`, `<tbody>` y `<tr>`.
* Celdas de encabezado (`<th>`) configuradas con el atributo `scope` para especificar si describen una columna (`scope="col"`) o una fila (`scope="row"`), garantizando accesibilidad para lectores de pantalla.
* Contiene los datos exactos de precios por hora, medio día (4 h) y día completo para los tres tipos de bicicleta (Urbana, Montaña y Eléctrica).

3. Tabla 2: Recorridos guiados

* Construida bajo la misma estructura semántica de tabla accesible (`<caption>`, `<thead>`, `<tbody>`, `th` con `scope`).
* La sección contenedora recibió un identificador único (`id="recorridos"`) para permitir la navegación directa mediante anidamiento de enlaces externos.
* Contiene los datos detallados de las rutas (Río y Parques, Sabores de Barrio, Reto Las Palmas) con su respectiva distancia, duración, nivel y precio por persona.

4. Información adicional al cliente

* Se agregó la nota informativa aclarando que todas las tarifas incluyen casco y candado.
* Se detallaron los horarios de salida de los recorridos (sábados y domingos a las 7:00 a. m.).
* Se incluyó una lista con viñetas (`<ul>`) especificando lo que el cliente debe llevar (ropa cómoda, agua, protector solar y documento de identidad).

5. Uso de rutas relativas y visualización del logo

* Como la página `tarifas.html` se encuentra dentro de la subcarpeta `paginas/`, se construyó la ruta del logotipo subiendo un nivel mediante `../`: `<img src="../img/logo.jpg" alt="Logo de Rueda Libre" width="40">`.
* Esto permitió que la imagen cargara de forma correcta sin romper la jerarquía del proyecto.

6. Enlaces cruzados y navegación entre carpetas

* Enlace desde la página de inicio (`index.html`) hacia la página de tarifas (`paginas/tarifas.html`).
* Enlace de retorno desde la página de tarifas hacia el inicio utilizando `../index.html`.
* Enlace directo desde la sección de recorridos guiados en la página de inicio apuntando exactamente a la tabla correspondiente mediante el ancla (`paginas/tarifas.html#recorridos`).

7. Verificación en DevTools (Network) y control de versiones

* Se revisó la pestaña *Network* (F12) confirmando que no existieran errores 404 y que tanto los archivos HTML como las imágenes cargaran con estado 200 (OK).
* Se ejecutaron los comandos de Git para guardar los cambios:
* `git add .`
* `git commit -m "feat: agrega la pagina de tarifas.html con tablas de precios, recorridos y navegacion cruzada"`

MINIRETO 5: Estructura semántica y organización del contenido
==================================================

Objetivo: organizar el contenido de las tres páginas con etiquetas HTML semánticas.

1. Estructura aplicada
- <header> identifica el encabezado de cada página.
- <nav> agrupa los enlaces principales: Inicio, Tarifas y rutas, y Reservas.
- <main> contiene el contenido principal; cada página debe tener un único main.
- <section> separa los temas principales.
- <article> agrupa cada servicio independiente de la página de inicio.
- <aside> contiene información complementaria, como los elementos que debe llevar el cliente y el horario de atención.
- <footer> contiene el nombre del negocio, correo y año.

2. Encabezados
- Se mantiene un solo <h1> por página.
- Los <h2> identifican las secciones principales y los <h3> los contenidos subordinados.
- La jerarquía de encabezados representa la organización del contenido, no el tamaño visual; los tamaños se controlan con CSS.

3. Rutas y navegación
- Desde index.html se enlaza a las páginas internas con rutas como paginas/tarifas.html y paginas/reservas.html.
- Desde archivos dentro de paginas/ se vuelve a la raíz con ../index.html y se enlaza entre páginas hermanas con tarifas.html y reservas.html.
- La hoja de estilos de las páginas internas se enlaza con ../css/styles.css.
- La lista del menú utiliza id="menu" para aplicar estilos compartidos.
- La página activa se identifica con class="activo" y aria-current="page".

4. Elementos no semánticos
- Se priorizan las etiquetas semánticas cuando describen el propósito del contenido.
- Los elementos <div> y <span>, si se necesitan, se reservan para agrupaciones o detalles sin una etiqueta semántica más adecuada.
- No se agregan contenedores innecesarios.

5. Verificación

MINIRETO 6: Formulario de reservas
==================================================

Objetivo: crear un formulario organizado con etiquetas accesibles y controles adecuados.

1. Estructura
- Se utiliza <form action="#" method="post"> como formulario de práctica.
- Los controles se agrupan en tres fieldset con legend: “Tus datos”, “Tu alquiler” y “Confirmación”.
- El formulario incluye nombre completo, documento, correo, celular, fecha, tipo de bicicleta, plan, cantidad, recorrido guiado opcional, comentarios opcionales y aceptación de políticas.
- Se incluye un botón para enviar el formulario.

2. Accesibilidad
- Cada control debe tener id y una etiqueta <label> asociada mediante for.
- Los controles enviados deben tener name.
- Las opciones relacionadas comparten name cuando corresponda.
- Se usan tipos adecuados como email, tel, date y number.
- La casilla de aceptación de políticas es obligatoria.

3. Justificación de tres decisiones
- <fieldset> y <legend> agrupan controles relacionados y explican el propósito de cada grupo.
- type="email", type="date" y type="number" ofrecen controles apropiados y validaciones básicas del navegador.
- <label> asociado mediante for e id permite identificar el campo y facilita activarlo al pulsar la etiqueta.

4. Limitación
- action="#" es provisional: no existe por ello un sistema real que reciba, almacene o confirme las reservas.
- Para recibir reservas reales será necesario conectar el formulario con un backend o servicio de formularios y definir el tratamiento de los datos personales.
